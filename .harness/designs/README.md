# Designs

Put durable design notes here when a change affects architecture, behavior, APIs,
security boundaries, data flow, or deployment contracts.

Use filenames like:

```text
YYYY-MM-DD-short-topic.md
```

Suggested structure:

```markdown
# Title

## Problem

## Current Behavior

## Proposed Design

## Alternatives Considered

## Risk And Compatibility

## Verification Plan
```

Keep designs source-backed. Link to concrete files and functions where possible.
